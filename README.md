# Сервис цен Binance

Сервис на Spring Boot периодически получает среднюю цену Binance, сохраняет данные в PostgreSQL и предоставляет их через REST API.

## Требования

- Java 21 (по заданию требуется Java 17 или новее)
- Docker и Docker Compose для запуска контейнеров и интеграционного теста с Testcontainers
- Доступ к настроенному URL Binance API, если планировщик обращается к настоящему API

## Запуск через Docker Compose

Скопируйте `.env.example` в `.env` и задайте собственный пароль PostgreSQL. Файл `.env` игнорируется Git и не должен попадать в коммиты.

```bash
cp .env.example .env
docker compose up --build
```

API доступно по адресу `http://localhost:8080`, PostgreSQL опубликован на порту хоста `5433`. При запуске приложения Liquibase создаёт или обновляет схему базы данных. Команда `docker compose down` останавливает сервисы, но сохраняет именованный volume `pgdata`. Используйте `docker compose down -v` только если намеренно хотите удалить данные базы.

Чтобы запустить приложение на хосте, оставив PostgreSQL в Docker:

```bash
cp .env.example .env
docker compose up -d db
./mvnw spring-boot:run
```

## Настройки

При локальном запуске Spring Boot читает необязательный файл `.env` из корня проекта. Compose тоже читает его и передаёт переменные контейнерам.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `POSTGRES_USER` | Обязательно | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Обязательно | Пароль PostgreSQL |
| `POSTGRES_DB` | Обязательно | Имя базы данных |
| `POSTGRES_HOST` | `localhost` | Хост базы данных; Compose задаёт `db` для контейнера приложения |
| `POSTGRES_PORT` | `5433` | Порт базы данных; Compose задаёт `5432` внутри своей сети |
| `BINANCE_BASE_URL` | `https://api.binance.com` | Базовый URL Binance API |
| `BINANCE_POLL_INTERVAL` | `PT30S` | Интервал планировщика в формате длительности ISO-8601, например `PT30S` |

## REST API

Параметры даты и времени задаются как моменты ISO-8601 в UTC, например `2026-11-01T00:00:00Z`. Для фильтрации периода используется `fetchedAt`; обе границы периода включаются. Торговая пара по умолчанию — `BNBUSDT`.

### Последняя сохранённая цена

```http
GET /api/v1/prices/latest
```

Возвращает самую свежую сохранённую запись с полями `symbol`, `price` и `fetchedAt`. Цена сериализуется как JSON-строка; `fetchedAt` указан в UTC с точностью до секунды. Если записей нет, возвращается `404`.

```bash
curl --noproxy '*' -i http://localhost:8080/api/v1/prices/latest
```

### Средняя цена за период

```http
GET /api/v1/prices/average?from=2026-11-01T00:00:00Z&to=2026-11-02T00:00:00Z
```

Возвращает `{"averagePrice": ...}`, где средняя цена представлена JSON-числом. Если начало периода позже конца, возвращается `400`; если за период нет записей — `404`.

```bash
curl --noproxy '*' -i 'http://localhost:8080/api/v1/prices/average?from=2026-11-01T00:00:00Z&to=2026-11-02T00:00:00Z'
```

### Цены с пагинацией

```http
GET /api/v1/prices?from=2026-11-01T00:00:00Z&to=2026-11-02T00:00:00Z&page=0&size=20
```

`page` нумеруется с нуля и по умолчанию равен `0`; `size` по умолчанию равен `20`, максимум — `1000`. Результаты сортируются по `fetchedAt DESC, id DESC`, чтобы порядок страниц оставался стабильным. Корректный запрос без записей возвращает `200`, пустой список `items` и метаданные пагинации. Некорректные параметры или обратный диапазон дат приводят к `400`.

```bash
curl --noproxy '*' -i 'http://localhost:8080/api/v1/prices?from=2026-11-01T00:00:00Z&to=2026-11-02T00:00:00Z&page=0&size=20'
```

### Тренд цены

```http
GET /api/v1/prices/trend?from=2026-11-01T00:00:00Z&to=2026-11-02T00:00:00Z
```

Тренд вычисляется сравнением первой и последней цен за период, упорядоченных по `fetchedAt` (затем по `id`): `UPWARD`, `DOWNWARD` или `FLAT`. Необходимы как минимум две разные записи, иначе endpoint возвращает `404`. Даты в ответе представлены в UTC в формате `yyyy-MM-dd`.

```bash
curl --noproxy '*' -i 'http://localhost:8080/api/v1/prices/trend?from=2026-11-01T00:00:00Z&to=2026-11-02T00:00:00Z'
```

## Архитектура и структура проекта

- `client/` содержит HTTP-клиент Binance и модель ответа.
- `service/` содержит сценарии сбора и чтения данных; контроллеры не обращаются к репозиториям напрямую.
- `repository/` содержит запросы Spring Data. PostgreSQL хранит цены как `numeric`, а в Java для денежных значений используется `BigDecimal`, а не `double`.
- `entity/` описывает сохраняемые записи. `dto/` задаёт публичную форму ответа отдельно от сущности базы данных.
- `config/TimeConfig` предоставляет внедряемый UTC `Clock`. Сервис сбора использует его для интервалов повторного запроса и значения `fetchedAt`; тесты могут управлять временем без ожидания реальных секунд.
- `src/main/resources/db/changelog/` содержит версионированные миграции Liquibase. Индекс `(symbol, fetched_at)` поддерживает выборки за период и сортировку по времени получения.
- `compose.yaml` запускает PostgreSQL и приложение. Многоэтапный `Dockerfile` собирает исполняемый JAR и запускает его на Java 21.

Планировщик обрабатывает ответы Binance `429`/`418`: если есть заголовок `Retry-After`, пауза берётся из него; если заголовок отсутствует или некорректен, используется задержка по умолчанию. Ошибки сервера, сети и сохранения обрабатываются так, чтобы единичный сбой не останавливал последующие запуски планировщика.

## Тесты

Запустить unit-тесты, MVC-тесты и интеграционный тест можно командой:

```bash
./mvnw test
```

`PriceQueryServiceTest` и `PriceCollectorServiceTest` проверяют бизнес-логику с Mockito. `PriceControllerTest` использует `@WebMvcTest` и MockMvc для проверки HTTP-статусов, параметров, валидации, типов JSON и метаданных страниц. `PriceApiL1Test` запускает Spring-приложение и Liquibase с PostgreSQL в Testcontainers и проверяет полный путь controller → service → repository. Внешний клиент Binance заменён заглушкой, поэтому тесты не зависят от сетевого доступа. Для интеграционного теста должен быть запущен Docker.

Запустить только интеграционный тест Layer 1:

```bash
./mvnw -Dtest=PriceApiL1Test test
```
